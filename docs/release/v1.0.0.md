# oh-my-ai Public V1.0.0 Release Notes (Draft)

> Draft release-preparation record. This document does not create a Git tag or
> publish a GitHub Release.

## Product

oh-my-ai is a portable harness that installs managed AI entry points while
preserving a user's existing configuration, then turns an explicit Work-start
request into reviewable repository-local planning artifacts.

## Public V1 scope

- Supported runtimes: Claude Code and Codex.
- Supported, verified platforms: macOS and Linux.
- Installation: clone the repository, run `make install-shared`, then verify
  with `make doctor-strict`.
- Explicit execution: `/work-start <task>` in Claude Code or `$work-start <task>`
  in Codex.
- Safety boundary: natural-language intent is suggestion-only. Only an
  explicit Work-start invocation runs the Engine. It creates artifacts under
  `.oh-my-ai/work-start/<timestamp>-<slug>/`, reports the files, and stops at
  `Needs human review` with Direct Handoff, Plan First, and Gather Context.
- Existing `CLAUDE.md` and `AGENTS.md` files are preserved; the installer owns
  only its managed public entries.

## Upgrade

For an existing clone, update the tracked source and rerun the managed
installation:

```bash
make update
make doctor-strict
```

`make update` runs `git pull` followed by `make install-shared`; it does not
replace user-owned instruction files.

## Known limitations

- Codex Hook trust requires the user to confirm the hook in `/hooks`.
- Model UI behavior remains a manual release gate: fixtures verify the shell
  contract, but they cannot prove that every provider UI stops its response or
  follows only a later explicit continuation choice.
- Post-execution suppression requires exact repository, runtime, session, and
  normalized-task correlation. If a verifiable session ID is unavailable, it
  fails open and leaves the normal suggestion visible.
- The repository-local state marker is best-effort; it is not Cloud Session
  Linking.
- macOS and Linux are verified. Other operating systems are not part of the
  Public V1 verification claim.
- This repository currently has no GitHub Actions workflow; the fixture and
  Doctor commands remain required release checks.
